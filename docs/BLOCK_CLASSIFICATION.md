## 1. Исследованные механики и подтверждённые факты

### 1.1 Установка факела
| Факт | Источник |
|---|---|
| Предмет факела — `VerticallyAttachableBlockItem(TORCH, WALL_TORCH, DOWN)`: перебирает направления из `ItemPlacementContext.getPlacementDirections()`; вертикальный вариант ставится, если опора **снизу**, иначе — настенный; вниз (на потолок) факелы не ставятся. В конце — `world.canPlace(state, pos, ShapeContext.absent())` | [код] `Items.java:336`, `VerticallyAttachableBlockItem.getPlacementState` стр. 37–54 |
| **Напольный** факел: `canPlaceAt` = `Block.sideCoversSmallSquare(world, pos.down(), UP)` → `isSideSolid(..., SideShapeType.CENTER)` — верхняя грань опоры должна покрывать **центральный квадрат** (шейп `createCuboidShape(7,0,7,9,10,9)`) | [код] `AbstractTorchBlock.java:37–39`, `Block.java:322–325`, `SideShapeType.java:17–19` |
| Следствие: напольный факел можно поставить на заборы, стены, верх цепи/столбов — всё, чья верхняя грань закрывает центр; **нельзя** на нижнюю плиту (верх пуст) | [код] + [предп.] для конкретных блоков — проверить тестом |
| **Настенный** факел: `WallTorchBlock.canPlaceAt` = опора с противоположной стороны `isSideSolidFullSquare(facing)` — нужна **полная** боковая грань | [код] `WallTorchBlock.java:73–77` |
| Целевая позиция должна быть заменяемой: `ItemPlacementContext.canPlace()` → `getBlockState(pos).canReplace(ctx)` (воздух, трава, 1 слой снега и т.п.) | [код] `ItemPlacementContext.java:54–56`, `AbstractBlock.canReplace` стр. 1520 |
| Факел снимается, если исчезла опора (`getStateForNeighborUpdate` → AIR) | [код] `AbstractTorchBlock.java:28–34`, `WallTorchBlock.java:101–105` |
| Свойства блоков факелов: `noCollision`, `breakInstantly`, `pistonBehavior(DESTROY)`; luminance: **torch 14**, **soul torch 10**, **redstone torch 7** (только горящий) | [код] `Blocks.java:1171–1175, 1961–1969, 2120–2124` |
| Редстоун-факел — источник сигнала (может включать механизмы) и гаснет при запитанной опоре | [вики], не проверено в коде |
| **Клик по интерактивному блоку** (сундук, дверь, рычаг, верстак…) без приседания вызывает `onUseWithItem`/`onUse` — блок откроется/переключится вместо установки. При `shouldCancelInteraction()` (приседание) и предмете в руке использование блока пропускается | [код] `ClientPlayerInteractionManager.interactBlockInternal` стр. 293–321 |
| Факел в жидкости: вода — заменяемая, но факел не waterloggable; ожидается смыв/выпадение | [предп.], проверить в игре; в планировщике запрещено (§4, L4) |

## 2. Предлагаемые категории (независимые, могут пересекаться)

Ключевая идея: **свойства блока** (что говорит игра) отделены от **правил поведения** (что делает мод). Категории — это предикаты над свойствами + небольшие курируемые списки.

### Слой свойств `BlockTraits` (вычисляется из API, на `BlockState`)
| Свойство | Как получить | Контекст? |
|---|---|---|
| `luminance` | `getLuminance()` | состояние |
| `opacity`, `lightFaces[6]` | `getOpacity`, `getCullingFace` (если `isOpaque && hasSidedTransparency`) | состояние (позиция почти не влияет) |
| `topCenterSolid` (опора напольного факела) | `isSideSolid(UP, CENTER)` + тег `unstable_bottom_center` неактуален для UP | состояние |
| `sideFullSolid[4]` (опора настенного факела) | `isSideSolidFullSquare(dir)` | состояние |
| `replaceable` | `canReplace(ctx)` | контекст (нужен ctx) → вычисляем при планировании |
| `collision` (пусто/низкая/частичная/полная), высота верха | `getCollisionShape` | состояние; у некоторых — позиция |
| `fluid` (нет/вода/лава, источник/поток) | `getFluidState()` | состояние |
| `fireDamaging`, `pathNodeType` | `PathNodeMaker.isFireDamaging`, `getCommonNodeType` (protected → access widener) | состояние |
| `emitsRedstone` | `emitsRedstonePower()` | состояние |
| `interactive` (клик что-то делает) | эвристика: блок переопределяет `onUse`/`onUseWithItem` (рефлексия по классу) **или** курируемый список/теги (`doors`, `trapdoors`, `fence_gates`, `buttons`, `beds`, `shulker_boxes`…) | см. §5 |
| `spawnFloorOk(type)`, `spawnSpaceOk(type)` | `allowsSpawning`, `isClearForSpawn`, spawn box | контекст (тип моба, мир) |
| теги | `isIn(BlockTags.*)` | — |

### A. Поверхности для установки факела
| Подкатегория | Правило | Примеры |
|---|---|---|
| A1 Опора сверху (напольный) | `topCenterSolid` у блока под позицией ∧ позиция `replaceable` ∧ не жидкость | камень, земля, доски, стекло, листва (полный шейп — [предп.]), верхняя плита, перевёрнутые ступени, заборы/стены (центр закрыт — [предп.]) |
| A2 Опора сбоку (настенный) | `sideFullSolid[facing]` у соседа ∧ позиция `replaceable` | полные блоки; **не** заборы, стены, нижние плиты сбоку (грань неполная) |
| A3 Невозможно | ни A1, ни A2 | нижняя плита (сверху), ковёр, кнопка, рельс, факел, жидкость, воздух |
| A4 Возможно с условием | клик по блоку **интерактивен** → нужно приседание (подтверждено кодом) | сундук, бочка, верстак, печь, дверь (верх), люк, калитка, рычаг, кровать, нотный блок, наковальня |
| A5 Технически можно, но нецелесообразно | опора нестабильна или «временна» | гравий/песок (упадут — [вики]), лёд (по [вики] лёд тает при block light > 11, а факел даёт 14 рядом с собой → лёд превратится в воду и смоет/сломает факел; не проверено в коде), листва (дерево срубят/опадёт), блоки, которые игрок может сломать по механике (полевые культуры — нет опоры), поршни/подвижные блоки, scaffolding, редстоун-механизмы |

### B. Запрещённые и непригодные места
- **B-игра (механика, не обсуждается):** позиция не `replaceable`; нет опоры A1/A2; жидкость в позиции; позиция пересекается с сущностью/игроком (`canPlace` с коллизией — у факела коллизии нет, так что сущности не мешают — [предп.]); вне досягаемости; вне world border.
- **B-мод (рекомендация по умолчанию, пользователь может снять):** A5-позиции; на опоре — интерактивный блок без возможности присесть; рядом с редстоун-механизмами; внутри чужих построек (определить нельзя → опция «не ставить на блоки из списка X»); на дорогах из нижних плит/ковров — не нужно.
- **B-пользователь:** «никогда не ставить на/рядом с» списком блоков (например, фасады, ферма).
- **B-план:** позиция допустима, но **не нужна** (не закрывает опасных мест) — это не категория блока, а решение планировщика.

### C. Опасные блоки и области
Опасность — свойство блока **плюс** правило распространения. Радиусы обоснованы механикой, а не одинаковы:

| Опасность | Что именно опасно | Распространение | Обоснование |
|---|---|---|---|
| Лава (источник/поток) | урон, поджог, смерть | нельзя стоять/идти; буфер **1** для пути (как ваниль), **2** по горизонтали для позиции, с которой ставим факел (поворот/толчок); вниз от уступа над лавой — запрет позиции у края | [код] соседство 1 у ванили; поток лавы в Overworld ~3 блока — [вики], не проверено; buffer 2 — рекомендация |
| Огонь, soul fire, горящий костёр, campfire | урон | блок + 1 | [код] `isFireDamaging` + соседство 1 |
| Magma block | урон, если стоять не приседая | только «стоять на» | [код] fireDamaging; ходьба приседая — [вики] |
| Кактус | урон при касании | соседние по горизонтали 1 | [код] DAMAGE_OTHER + соседство |
| Sweet berry bush, wither rose | урон внутри | блок | [код] |
| Powder snow | проваливание, заморозка | блок (как пол и как пространство) | [код] POWDER_SNOW |
| Pointed dripstone (сталагмит) | урон при падении на него; сталактит падает | позиция над сталагмитом; колонна под сталактитом | [код] DAMAGE_CAUTIOUS; падение сталактита — [вики] |
| Обрыв (падение > 3) | урон от падения | позиции для установки — не ближе 1 блока к краю обрыва глубже `maxFallHeightNoWater`; путь — решает Baritone | [Baritone] `maxFallHeightNoWater = 3` |
| Вода глубокая / поток / bubble column | утопление, снос | путь — Baritone; позиции для установки — не в воде | [Baritone] `avoidWalkingInto` |
| Cobweb, honey, soul sand, powder snow | замедление/застревание | только штраф/обход | [код] STICKY_HONEY; [Baritone] |
| Big dripleaf | наклоняется → падение | не стоять | [код] TRAPDOOR-тип |
| Sculk sensor / shrieker | вибрации → Warden | опция: не подходить ближе 8 | радиус 8 — [вики], не проверено; категория «последствия» |
| Нажимные плиты, tripwire | ловушки (TNT, раздатчики) | не наступать | [Baritone] tripwire не проходим; плиты — [предп.] |

Приседание как защита от падения с края — штатная механика; использовать при установке у края по опции.

### D. Препятствия и проходимость
| Подкатегория | Примеры | Примечание |
|---|---|---|
| D1 Полностью блокирует | полные блоки, стекло | `collision` полный |
| D2 Проходимо | воздух, трава, цветы, факелы, ковры, снег 1–7 (низко), кнопки, рельсы | проходимость ≠ безопасность (рельс + вагонетка, ягоды — урон) |
| D3 Нужен прыжок | плиты/ступени (полблока — шаг без прыжка), полный блок (прыжок), заборы/стены (1.5 — **непреодолимы**) | высота коллизии; заборы — FENCE в ванили |
| D4 Можно изменить, но **без разрешения нельзя** | двери, калитки, люки (открыть), любые блоки (сломать), свои факелы | Baritone `allowBreak/allowPlace`; открытие дверей — отдельное разрешение (D-5) |
| D5 Лазание | лестницы, лианы, scaffolding, twisting vines | Baritone: `allowVines=false` по умолч. |

### E. Пригодность для спавна
Не по типу пола. Позиция-кандидат = (пол `allowsSpawning(type)`) ∧ (ноги и голова `isClearForSpawn`) ∧ (spawn box свободен) ∧ **block light = 0** ∧ (в зоне анализа). Проверяется на 3 репрезентативных видах (zombie, spider, enderman). Категория блоков здесь только **ускоряет** отсев (например, «никогда не пол» = стекло/листва/плиты), а итог — по ванильным проверкам (D-24).

### F. Свет
- **F1 Излучатели** (`luminance > 0`) — автоматически, с учётом состояния.
- **F2 Переменные излучатели** — свет зависит от состояния, которое меняется само или игроком: печь/коптильня/доменная печь (lit), redstone lamp, copper bulb, свечи и торты со свечами, костры, sea pickle (количество/вода), respawn anchor, cave vines (ягоды), light block (уровень), redstone torch, глоу-лишайник (стабилен). Курируемый список + автодетект: блок имеет свойство `lit`/`level`/`candles`/`charges`. По умолчанию **не считаются защитой** (D-21).
- **F3 Влияние на распространение** — opacity и грани (автоматически); важно для `LightSim`.
- Реальный свет мира берём из `getLightLevel(LightType.BLOCK, pos)`; `LightSim` нужен только для **будущих** факелов.

### G. Дополнительные категории (предлагаю)
| Категория | Зачем |
|---|---|
| G1 «Не кликать» (интерактивные) | установка на такие блоки — только с приседанием, иначе откроется сундук/дверь (подтверждено кодом) |
| G2 «Не трогать / чужое» | блоки, рядом с которыми игрок не хочет факелов (фасады, фермы, редстоун) |
| G3 «Нестабильная опора» | гравий, песок, concrete powder, scaffolding, листва — факел может упасть позже |
| G4 «Последствия» | sculk sensor/shrieker, tripwire, нажимные плиты, TNT рядом, turtle eggs (растаптываются), грядка (растаптывается прыжком) — не опасны сразу, но действия мода вызовут эффект |
| G5 «Свои факелы» | различать факелы, поставленные модом, для отчёта и (по разрешению) отмены |

## 4. Пользовательские настройки и приоритеты

### Слои (сверху — сильнее)
| Слой | Что это | Кто меняет |
|---|---|---|
| **L4 Абсолютные запреты** | нельзя: ставить туда, где игра запрещает; ставить в жидкость; стоять/идти в лаву, огонь; ломать/открывать без явного разрешения; работать вне Overworld; продолжать после урона выше порога/смерти | никто |
| **L0 Механика игры** | опора, заменяемость, коллизия, свет, спавн — из API | никто (это факт) |
| **L1 Автосвойства** | `BlockTraits` и выведенные категории (fireDamaging, pathNodeType, interactive-эвристика) | никто; можно только **дополнить** через L3 |
| **L2 Рекомендации мода** | курируемые списки: опасные (C), G1–G4, F2 | пользователь (добавить/убрать) |
| **L3 Пользователь** | добавить/исключить блоки из категорий L2; веса и радиусы | пользователь |

### Правила разрешения конфликтов
1. **Разрешение действия = L4 ∧ L0 ∧ (L1/L2/L3 после переопределений).** Пользователь может **сузить** допустимое всегда, а **расширить** — только в мягких (предпочтительных) правилах, но никогда за пределы L0 и L4.
2. «Опасный» описывает **стоять/идти/находиться рядом**; «поверхность для факела» описывает **грань-цель**. Это разные роли: блок может быть опасным и при этом опорой для факела. Пример: магма в «опасных» и разрешена как опора → факел на магму ставится **с безопасной позиции**, на магму не наступаем.
3. Исключение блока из «опасных» убирает только **мягкое** избегание (буфер, штраф пути). Физическое ограничение остаётся: лава остаётся непроходимой и запрещённой (L4 + Baritone).
4. Если блок подходит для установки, но факел там не нужен — факел не ставится (решение планировщика, категории не влияют).
5. Если пользователь добавил блок в «опасные», а Baritone всё равно идёт через него — передаём список в `blocksToAvoid` на время сессии (с восстановлением). Если блок в пути неизбежен — стоп с причиной, а не тихое продолжение.
6. Неизвестный блок (сторонний мод, ни один признак не определён): для установки — по свойствам L0; для опасности — **консервативно** (обход, если `isFireDamaging`/жидкость/урон по тегам, иначе нейтрально) и пометка «неизвестно» в информации о блоке.

### UI в Meteor (рекомендация — штатные средства)
- Категории L2 = `BlockListSetting` в отдельном модуле-конфиге `TorchBlocks` (поиск, две колонки, сброс, сохранение в NBT — всё уже есть в Meteor).
- Два списка на категорию: «добавлено пользователем» и «исключено пользователем» (поверх встроенных значений), чтобы сброс и обновления мода работали предсказуемо.
- Просмотр свойств блока: команда `.torchblock info [<блок> | взгляд]` — выводит L0/L1 (помечено «игра») и L2/L3 (помечено «мод» / «вы»), итог для ролей «опора / стоять / путь / спавн / свет».
- Экспорт/импорт: штатное копирование настроек модуля в буфер обмена Meteor (без своей системы файлов).
- Своё окно с таблицей свойств — **не в первой версии** (дорого, ценности мало по сравнению с командой `info`).

## 5. Архитектура

```
Registries.BLOCK (ванильные + модовые)            Meteor settings (L2/L3)
        │ lazy, по BlockState                          │
        ▼                                              ▼
  TraitsProvider (version adapter) ──▶ BlockTraits ──▶ CategoryResolver ──▶ роли:
   getLuminance, getOpacity, faces,      (кэш          (предикаты L1 +      canSupportFloor/Wall,
   isSideSolid(CENTER/FULL), collision,   Identity-     списки L2 ± L3,      standHazard(radius),
   fluid, isFireDamaging, pathNodeType,   HashMap)      правила L4)          pathAvoid, spawnFloor,
   emitsRedstone, tags                                                       lightSource(stable?)
                                                                     │
                                       core (LightSim, SpawnModel, Planner) получает только роли/числа
```

- **Динамически (API):** luminance, opacity, грани света, опорные грани, коллизия, жидкость, fireDamaging, тип узла пути, редстоун, теги. Работает для модовых блоков без настройки.
- **Курируемо (маленькие списки по id, данные, не код):** опасности, которых нет в API (powder snow, сталагмиты, big dripleaf, sculk), G1 (дополнение к эвристике), G3, G4, F2.
- **Контекстно (на позиции во время планирования):** заменяемость, спавн (зависит от типа моба), освещённость, «у края обрыва», «рядом с лавой», связность.
- Версионно-зависимый код — один класс `TraitsProvider_1_21_1`; при порте меняются вызовы API, категории и ядро остаются.
- Почему так, а не иначе: таблица на все блоки вручную — устареет и не поддержит моды; полностью «умная» автоклассификация опасностей невозможна (урон не описан данными блока). Гибрид «API + маленькие курируемые списки + контекст» — минимальная система, закрывающая все требования.

## 6. Нестандартные ситуации
| Ситуация | Поведение |
|---|---|
| Опора — интерактивный блок | приседание на время клика (штатно) или пропуск позиции, если приседание выключено пользователем |
| Опора исчезла после установки | факел сломан игрой → место снова опасно → в план |
| Блок изменился между планом и кликом | перепроверка L0 перед кликом; при несоответствии — пересчёт |
| Лава потекла во время сессии | инвалидация кэша по `BlockUpdateEvent`, пересчёт буферов; если путь перекрыт — стоп |
| Модовый блок без признаков | «неизвестно»: для света — по `getLuminance/opacity`; для опасности — консервативно; в `info` видно |
| Пользователь убрал лаву из опасных | исчезает буфер; заход в лаву по-прежнему запрещён |
| Блок и опасный, и опора | опора используется только с безопасной позиции |
| Редстоун-факел у игрока в хотбаре | не используется (D-26) |

## 9. Рекомендуемый вариант
**Гибрид: свойства из API на `BlockState` (кэш) + небольшие курируемые списки по id для того, чего API не знает + контекстные проверки в планировщике + жёсткие слои L0/L4, которые пользователь не может отменить.**
Лучше альтернатив, потому что:
- «ручная таблица всех блоков» устаревает с каждой версией и не видит моды;
- «только API» не знает опасностей вроде сталагмитов и sculk;
- «одна категория хорошо/плохо» не выражает разницу между «опора», «стоять», «идти», «спавн», «свет» — а это именно то, что путает при автоматизации.
Система добавляет одну новую сущность (`BlockTraits`) и один резолвер; категории — данные, новые добавляются без переписывания.
