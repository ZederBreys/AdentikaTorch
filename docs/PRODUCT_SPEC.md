# Описание продукта — Torch Automation

Версия концепции: 2 (2026-10-25, по уточнениям пользователя). Предыдущая версия (англ.) заменена; технические факты — в `TECHNICAL_RESEARCH.md`.

## 1. Цель
Клиентский мод для **Minecraft Java 1.21.1, Overworld**, который **умно** расставляет факелы так, чтобы на территории игрока **ночью не появлялись враждебные мобы, возникающие из-за темноты**, и по ней можно было безопасно ходить.

«Умно» означает:
- место для факела выбирается **расчётом**, а не «каждые N блоков»: алгоритм покрывает светом всю нужную зону минимальным (насколько позволяет эвристика) числом факелов;
- **обязательно учитываются все уже существующие источники света** (факелы, фонари, светокамень, лава и т.д.) — мод **никогда** не ставит факел туда, где света уже достаточно;
- проверяются правила спавна 1.21.1, а не «свет = 0 → факел».

Критерий «достаточно света» (подтверждено кодом 1.21.1): в блоке, где стояли бы ноги моба, **block light ≥ 1**. Ночью небо не защищает, поэтому sky light не учитывается.

Что светом **не** предотвращается (мод честно об этом сообщает): слаймы в слайм-чанках, стражи у монументов, фантомы, спавнеры и trial spawners, рейды, Warden, мобы из структур при генерации. Болотные слаймы (≥ 8) и патрули (≥ 9) — отдельные необязательные профили.

## 2. Режимы работы

### Режим 1 — «Сопровождение» (игрок ходит сам)
- Игрок включает режим и **сам** ходит по миру.
- Когда рядом (в пределах досягаемости) есть место, где не хватает света, и факел, поставленный **в рассчитанную точку**, покроет эту темноту, мод ставит факел сам.
- Мод не управляет движением игрока; только поворот головы и обычный клик установки.
- Факел ставится только если он нужен по плану (см. §4), а не просто потому, что рядом темно.

### Режим 2 — «Автопроход» (мод ходит сам)
- **2a. По выделенной области:** игрок выделяет область; мод сам ходит (Baritone) и ставит факелы, **пока вся область не покрыта** (или пока не кончатся факелы / не наступит условие остановки).
- **2b. Без выделения:** мод сам ходит и ставит факелы вокруг **точки старта** в пределах обязательных ограничений: радиус по горизонтали, окно по высоте (см. §3), лимит факелов. Останавливается, когда в этих пределах не осталось **досягаемых** непокрытых мест.

### Режим 3 — «Подсветка»
- Показывает рядом с игроком **чанки**, где есть тёмные места, и сами **места** (блоки), где может появиться моб, а также **рекомендуемые точки** для факелов.
- Ничего не ставит. Выключена по умолчанию.

### Пещерный режим (для режимов 1, 2, 3)
Отдельный режим анализа для пещер и шахт:
- рассматриваются только места, **связанные по воздуху** с игроком (та же пещерная система), а не все тёмные места под землёй;
- большое окно по высоте, нет требования «рядом с поверхностью»;
- факелы чаще ставятся на стены (настенный факел), т.к. в узких тоннелях это экономнее;
- Baritone по умолчанию **не копает** и не строит (только ходит).

## 3. Какую зону считать (чтобы не «освещать шахту под ногами»)
| Режим | Что попадает в анализ |
|---|---|
| Выделенная область (2a) | только блоки внутри выделения |
| Сопровождение (1), автопроход без выделения (2b), подсветка (3) — **поверхностный** режим | (а) окно по высоте относительно игрока/точки старта: **настраивается** «блоков вниз» и «блоков вверх»; (б) только места, **связанные по воздуху** с областью, где находится игрок (нельзя дойти — не считается: закрытая шахта под землёй не попадёт); (в) опция «только у поверхности»: место не глубже N блоков от верхнего твёрдого блока колонки |
| Пещерный режим | окно по высоте больше; связность по воздуху от игрока обязательна; требование «у поверхности» выключено |

Неизвестные (незагруженные) чанки = «неизвестно», не «безопасно».

## 4. Как мод решает, куда ставить факел
1. Скан зоны: для каждого блока — может ли там появиться моб (поверхность, место, хитбокс по правилам 1.21.1) и **текущий** block light из игры (это автоматически учитывает все существующие источники).
2. Опасные места = могут появиться мобы **и** block light = 0.
   - **Места на «неспавнящих» блоках не опасны и не освещаются**: листва (деревья), стекло, нижние плиты, ступени, ковры, снег 2–7 слоёв, люки, рельсы, кнопки/нажимные плиты, яркие блоки (glowstone, sea lantern, froglight…), вода для наземных мобов и т.д. Если игрок сделал пол из таких блоков, мод эту территорию не освещает; **там, где такой пол заканчивается и начинается обычный тёмный пол, места снова опасны** и попадают в план. Полный список и проверка по коду — `TECHNICAL_RESEARCH.md` §8.9.
   - Решение принимается теми же функциями игры, что и на сервере, а не захардкоженным списком.
   - Биомы без естественного спавна монстров (грибные поля, глубокая тьма) по умолчанию не освещаются; опция `include-no-monster-biomes` включает их (мобы могут прийти из соседних биомов).
3. Кандидаты для факела: напольный (на верхнюю грань опоры) и настенный (на боковую грань) — только туда, где установка возможна.
4. Для каждого кандидата расчётом распространения света (−1 за блок, с учётом стен, плит и т.п.) определяется, какие опасные места он закроет.
5. Планировщик выбирает факелы, закрывающие больше всего опасных мест (жадное покрытие с детерминированным выбором при равенстве). Это эвристика: результат близок к минимуму, но не гарантированно минимален.
6. После каждой установки свет перечитывается из игры, план пересчитывается.

## 5. Наблюдаемость («как Baritone»)
Игрок должен видеть процесс:
- путь Baritone (его собственная отрисовка) и **следующую цель** мода;
- **запланированные факелы** — полупрозрачные маркеры в точках установки (с гранью опоры);
- **опасные места** — боксы; уже закрытые — не рисуются или другим цветом;
- текущий факел, который ставится сейчас, — выделен;
- HUD-строка: режим, состояние (идёт / пауза / стоп + причина), сколько факелов поставлено / осталось по плану / есть в хотбаре, сколько опасных мест осталось и сколько из них недосягаемо.

## 6. Управление и безопасность
- Ничего не начинается само при загрузке мира/мода. Каждый режим включается явно; отмена — мгновенно (клавиша + кнопка).
- Режим 2 не перехватывает активную задачу Baritone без явного подтверждения; глобальные настройки Baritone молча не меняются (предлагается временно выключить ломание/постройку с восстановлением).
- Остановка с понятной причиной: нет факелов, повторные неудачи пути, повторные отказы установки сервером, выход из зоны, смерть, дисконнект, смена мира/измерения, игрок сам начал двигаться (в режиме 2, настраивается).
- Факелы — только из хотбара (перенос из инвентаря — отдельной опцией позже).
- Только обычные клиентские действия; без обхода античита, подмены пакетов и «тихих» поворотов. Сервер может запрещать автоматизацию — это ответственность игрока; мод предупреждает при первом включении режимов 1 и 2.

## 8. Критерии приёмки первого полного релиза
1. Сборка проходит документированной командой (JDK 21).
2. Подсветка находит опасные места и **не** помечает: стекло, люки, листву, нижние плиты, места без пространства, жидкость, освещённые места.
3. Ни один режим не ставит факел, если все места, которые он закрыл бы, уже освещены существующим светом.
4. Превью плана и фактическая установка используют один и тот же расчёт.
5. Поверхностный режим не помечает изолированные пещеры/шахты под игроком (связность + окно по высоте).
6. Пещерный режим покрывает связанную с игроком пещеру.
7. Режим 2a завершает выделенную область или останавливается с причиной; 2b — не выходит за радиус/окно/лимит.
8. Успех установки засчитывается только после подтверждения миром; отказы — ограниченные повторы и стоп.
9. Все автоматические действия видимы и отменяемы мгновенно.
10. Юнит-тесты ядра (свет, опасные места, планировщик); всё, что требует игры, — в ручном чек-листе с результатами.
